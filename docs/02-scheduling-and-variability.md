# 2.0实务二：排程方法、波动与验证

[返回知识库](../README.md) · [配套完整案例](01-end-to-end-case.md)

> 本文区分通用概念、SLIM论文事实和产品设计建议。比较表用于确定验证方向，不承诺某个算法在所有工厂最优。

## 1. 排程要先定义问题，不能先选算法

把需求写成六项：决策对象、时间范围、可选资源、硬约束、优化目标、重算触发条件。

例：未来一个班次，为已到站且可放行的光刻Lot分配机台和顺序；必须满足工序先后、资格、掩模和设备日历；优先满足有效生产目标，再减少设置损失与不必要任务变动；新WIP、故障、Hold、计划变化触发局部或全量重算。

“优先满足目标”还要具体定义是总欠产量、延期订单数、加权延期还是瓶颈缺料时间。多个目标冲突时，应约定优先层级或经过业务认可的权重，不能让研发凭感觉决定。

## 2. 方法选择矩阵

| 方法 | 决策依据 | 值得验证的场景 | 主要盲区 |
|---|---|---|---|
| FIFO先进先出 | 到达先后 | 作为透明基线、相似任务的同分规则 | 不反映计划缺口、资格稀缺或设置损失 |
| EDD交期优先 | 最早截止日期 | 交期口径明确、任务较独立 | 最早交期未必剩余工作最急，可能频繁切换 |
| 最小松弛时间 | 交期减当前时间减剩余预计历时 | 希望考虑剩余工作量 | 剩余时间预测不准，排序容易抖动 |
| Critical Ratio | 剩余可用时间/剩余工作时间 | 用比例比较不同规模任务的紧迫性 | 分母和单位要明确，不足以解决资源分配 |
| 短加工时间优先 | 当前任务加工时长 | 检查平均等待与交期权衡 | 长任务可能长期被推迟；不代表晶圆厂通用最优 |
| 设置族连续加工 | 尽量延续当前设置 | 切换损失明显 | 为凑量造成欠产或时间窗风险 |
| 瓶颈供料规则 | 下游所需合格WIP | 避免瓶颈饥饿 | 只看总量可能给错产品、错误工序供料 |
| SLIM的产品工序协调 | 产出计划、目标WIP、IPQ、SS/BI及资源约束 | 类似论文中重入、资格受限制造 | 依赖目标可行性和数据，模块规则不能混成一式 |
| CP/MILP等优化模型 | 显式变量、约束、目标 | 多资源复杂组合、需分析可行性 | 建模和求解成本；大规模和实时性要实测 |
| 离散事件仿真 | 状态、事件及策略随时间演变 | 比较故障、波动和策略效果 | 仿真本身不自动找到最优策略 |

Google的Job Shop官方示例展示了工序先后与同一机台不能重叠等约束，以及以完工跨度为目标的建模。真实晶圆厂还要增加资格、掩模、批处理、重入与质量等约束；示例目标不一定符合客户交付目标。[OR-Tools Job Shop](https://developers.google.com/optimization/scheduling/job_shop)。

## 3. 可行解、最优解和好用的方案不是一回事

| 结论 | 可以说什么 | 不可以说什么 |
|---|---|---|
| 找到可行解 | 在已建模约束和输入下，存在安排 | 已证明这是最优安排 |
| 找到更好解 | 比同口径基线的目标值更好 | 对所有业务指标都更好 |
| 求解超时 | 在计算预算内未得到所需结果 | 一定没有可行方案 |
| 模型证明不可行 | 当前模型和数据下无法同时满足限制 | 现实工厂永远无法生产 |
| 现场成功执行 | 该范围方案可执行 | 已适用于所有产品和设备 |

不可行时应提示冲突：例如“两批都只能P02，必须13:30前完成，但只有一小时可用”。展示扩大时间窗、增加经批准资格、调整需求等情景，不能静默去掉约束。

## 4. 用一个能手算的例子理解波动

**独立教学例子**：一台机器，每件加工1小时，无切换、故障和搬运延迟，初始为空。

| 到达方式 | 到达时刻 | 等待时间 | 平均等待 |
|---|---|---|---|
| 均匀到达 | 0、1、2、3小时 | 0、0、0、0小时 | 0小时 |
| 成组到达 | 0、0、2、2小时 | 0、1、0、1小时 | 0.5小时 |

两种方式机器都在0–4小时连续完成4件，产出相同，但后一种等待更长。不能仅根据机器忙不忙或本班完成几件判断流动是否健康。

再看能力余量：本来每小时来1件、机器恰好每小时完成1件。若设备停1小时，恢复后仍每小时来1件且只能完成1件，积压无法靠原速率自动消除。需要需求暂缓、合格替代能力、额外时间或减少实际损失。这里是确定性算例，不是整厂排队预测公式，也没有宣称“85%是全行业最佳利用率”。

## 5. 为什么有时应该少投，有时应该保留缓冲

| 现象 | 先诊断什么 | 可验证的动作 |
|---|---|---|
| 全线WIP高但瓶颈仍缺料 | WIP产品、工序、资格与到达时点 | 调整上游优先级，而不是继续盲目投料 |
| 瓶颈前一直有大量合格料 | 缓冲是否超过波动保护需要 | 分阶段降缓冲并监控产出与缺料 |
| 非瓶颈设备空闲 | 是否只是目标已满足或下游拥堵 | 不为提高局部开机率制造库存 |
| 缓冲太低导致产出损失 | 上游波动与恢复能力 | 增加适配缓冲或降低波动 |
| 排程频繁变化 | 输入噪声、事件触发、目标冲突 | 冻结区、变化惩罚、局部修复 |

SLIM强调合理WIP配置和供料，不意味着所有瓶颈前的库存都应增加。[原论文pp.64–70](https://pubsonline.informs.org/doi/10.1287/inte.32.1.61.15)。

## 6. 最小可验证的调度规则

以下为教学设计，不是SLIM原始伪代码。

```text
读取一致的数据快照
按工序、Hold、资格、材料、工具、设备状态过滤不可行组合
保留已开工且不可中断的任务
识别唯一资源或稀缺资源任务
按已批准的目标比较候选方案
检查机台、掩模、材料等资源的时间冲突
输出任务、未排原因、输入版本和解释
发布前复核关键状态；发生变化则拒绝或重新计算
```

数据过期、目标WIP为零、IPQ为负、工序结束后已无下一瓶颈、返工出现新工序实例，都要单独定义处理。模型不能用零除法或默认值把异常变成正常推荐。

## 7. 仿真与历史回放如何避免“看起来很好”

1. 固定比较范围、原策略、产品结构、需求和状态口径。
2. 回放时只提供当时可知信息；10:15给出的12:00修复预测不能回填成08:00已知。
3. 校准加工时间、故障、维护、搬运、Hold和资格；不要只用理想加工时间。
4. 有随机性时使用多个运行样本并报告分布或区间，不只挑最好的一次；样本量由差异和不确定性决定。
5. 对比交付、周期、产出、质量保护、WIP、设置和计划稳定性。
6. 仿真更优仍需影子和建议模式验证，特别记录“不采纳原因”。

### 试验记录模板

| 字段 | 填写要求 |
|---|---|
| 试验编号与假设 | 例如减少设置能否改善欠产而不增加超时批次 |
| 输入快照和规则版本 | 可重现，明确截止时间 |
| 基线与候选 | 比较算法、参数和目标相同部分 |
| 保护指标 | 良率、硬约束、产出等不得被静默牺牲 |
| 结果 | 总体及分产品，不只单个均值 |
| 不确定性 | 仿真假设、缺失数据、未覆盖异常 |
| 决策 | 继续试点、修数据、修改规则或停止 |
