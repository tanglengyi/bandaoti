# 2.0实务一：一张订单、三个批次、两台设备

[返回知识库](../README.md)

> 本文为完整教学案例。全部编号、数量、日期、工时、权限和页面均为假设，不是三星、通力或目标公司的实际数据。案例中的D0、D5、D29、D30为相对日期；小时用于D5的局部排程。局部一小时工序不代表整条制造周期。

## 1. 客户要的数量，怎样变成投片数量

订单SO-001要求产品P在D30交付24,000颗合格封装芯片，允许从多个合格批次供货。假设产品版本与客户要求均已确认。

| 供需项 | 数量与状态 | 本次能否抵扣 |
|---|---|---|
| 客户订单 | 24,000颗合格成品 | 需求 |
| 已放行成品库存 | 3,000颗，未分配其他订单 | 全部预留给SO-001 |
| 质量隔离成品 | 300颗，尚未放行 | D0不计入可用供给 |
| 现有在制A | 10片晶圆，处于较后段工序 | 预计贡献3,900颗，尚非合格成品 |
| 新投入批次 | 待计算 | 采用新投片到成品的计划转换率 |

为区分不同位置的良率口径，作如下简化：新投晶圆每片400个理论Die，前道至电测的综合计划合格比例90%，后段计划合格比例95%，因此每片新投晶圆预期产出400×0.90×0.95＝342颗成品。A已经通过部分损失阶段，采用其当前位置到交付的剩余预测390颗/片，不能再次乘整条路线的90%和95%。

```text
尚需新投贡献 = 24,000 − 3,000 − 3,900 = 17,100颗
新投晶圆需求 = 17,100 / 342 = 50片
本案例标准投片批量 = 25片
新建批次B、C，各25片
预计总供给 = 3,000 + 3,900 + 2×25×342 = 24,000颗
```

这里只是期望值意义上的平衡，没有良率不确定性的额外保护。对交付可靠性要求高时，应评估预测分布、备份供给和风险，而不是认定50片保证产出17,100颗。还有路线周期、物料、各工序与后段能力的可行性需要检查。

**数据操作**：计划员预留3,000颗成品；将A的预期贡献关联SO-001；建立B/C的生产需求。需求分配记录使用“预期贡献”和“实际合格数量”两个字段，避免系统把预测当成可出货库存。

## 2. 原材料净需求与投料不是一回事

假设B/C需要50片合格空白硅片。当前库存35片，其中5片隔离，另有10片确认在投料日前到货并完成检验，无其他预留和安全库存要求。

```text
当前可用 = 35 − 5 = 30片
投料日前预计可用 = 30 + 10 = 40片
新增缺口 = 50 − 40 = 10片
假设采购最小批量为25片，采购建议为25片
全部按期放行后供给 = 30 + 10 + 25 = 65片
实际投料仍为50片，剩余15片进入可用库存
```

采购批量大，不代表必须多投15片。物控负责保证50片可用，计划员依据计划和下游能力批准投料，仓库执行领料并保留材料批号，MES绑定B/C晶圆身份。

本案例假定这些到货和放行在D0已完成；此后B/C经前序工序，在D5进入下述光刻区域。A在D5也到达该设备区，但处于其产品路线较后的另一个光刻步骤。这体现了重入：同一个设备区可以承接不同路线位置。

## 3. D5的排程快照

以下只演示一个设备区。工艺细节抽象为“一次不可中断任务”；即使A只有10片，本例也假定该任务占1小时，非实际设备工时模型。

| 属性 | A | B | C |
|---|---|---|---|
| 晶圆数 | 10 | 25 | 25 |
| 到达顺序 | 第一 | 第二 | 第三 |
| 本地完成目标 | 12:00 | 13:30 | 11:00 |
| 合格设备 | P01 | P02 | P01、P02 |
| 预计加工时长 | 1小时 | 1小时 | 1小时 |
| 初始判断 | 相对不紧急 | 产品工序有生产缺口 | 产品工序有生产缺口 |

假设两台设备当前设置兼容，相关掩模不冲突，搬运和装载在排程时间内已包含；无额外最小等待或硬性工序时间窗。表中本地完成目标是内部管理目标，不是工艺超限报废的硬时限，也不是客户最终交期。

08:00初始候选方案V1：P01上C 09:00–10:00、A 10:00–11:00；P02上B 09:00–10:00。给C使用P01，是为了保留B唯一合格的P02。方案尚须执行前复核。

这里使用约束过滤与业务规则演示，并未实现SLIM全部SS/IPQ公式；“存在生产缺口”是假定上游模型已提供的结果。

## 4. 真实工厂一天应该怎样调研：D5跟班脚本

本表为模拟工作日，不冒充现场观察记录。用它去对照真实班次，记录差异。

| 时间 | 人在做什么 | 看什么页面/资料 | 决策及记录 |
|---|---|---|---|
| 07:45 | 班组长交接夜班未完成任务、设备与质量异常 | 交接班清单 | 对实物、系统和待处理事项逐项确认 |
| 08:00 | 计划员检查SO-001的供给和当班目标 | 需求贡献、欠产列表 | 确认B/C目标仍有效，形成V1 |
| 08:15 | IE与调度查看瓶颈、资格与队列 | WIP、设备资格、排程 | 保留B的唯一机台，不按到达顺序一刀切 |
| 08:30 | 物控发现分配给B的工艺用料未完成放行 | 按任务物料可用性 | B不得09:00开工，暂估11:30可用 |
| 08:40 | 调度更新V2；主管确认异常责任人 | 任务变化与缺料单 | 保留P01任务，B暂排11:30，执行前再确认 |
| 09:00 | 现场按任务送C进P01，系统复核并进站 | 班组任务、进站检查 | C开始；P02因无可执行任务未加工B |
| 10:00 | C完成，A进入P01；P02发生故障 | 加工事件、设备告警 | 撤销B在故障期的任务，设备人员接单 |
| 10:15 | 设备工程师给出12:00维修完成预测 | 维修工单与恢复预测 | 预计12:30完成工艺复资格，不提前视为已恢复 |
| 11:00 | A完成；销售提出另一订单的加急批U | 队列、加急需求单 | U已完成前序且仅P02合格，需1小时 |
| 11:30 | B物料正式放行并送达 | 质量状态、物理位置 | 解除缺料限制，但仍受设备不可用限制 |
| 12:00 | P02维修完成，开始复资格 | 设备维修与资格记录 | 只更新维修状态，不直接开放生产 |
| 12:15 | 计划与调度向业务负责人解释B/U冲突 | 两个候选方案 | 选择先B；U本地目标改为14:30并获确认 |
| 12:30 | P02通过资格检查且材料工具有效 | 资格生效、MES复核 | 发布V3，B 12:30–13:30，U 13:30–14:30 |
| 14:30 | 制造主管和IE核对实际完成与等待 | 当班达成与异常时段 | 不把缺料等待全部记成设备故障损失 |
| 班末 | 班组长交接后续工序，计划员更新预期交付 | 未结事项、WIP与预测 | 本地加工完成不等于SO-001已完成 |

“工艺用料”是本例抽象资源，实际必须明确物料号、批号、保质期和具体可用条件；不能拿这张表当真实光刻胶管理规范。

## 5. 插单：为什么P01空闲也帮不了忙

U是另一个订单的既有WIP，不增加SO-001的数量。11:00收到加急请求时，U和B都仅P02合格。U申请13:30前完成本地工序，B原目标也是13:30。

| 方案 | P02第一项 | P02第二项 | 对目标的影响 |
|---|---|---|---|
| 先B | B 12:30–13:30 | U 13:30–14:30 | B不迟；U较请求晚1小时 |
| 先U | U 12:30–13:30 | B 13:30–14:30 | U不迟；B较原目标晚1小时 |
| 用P01分流 | 不成立 | 不成立 | P01无B/U资格，不能靠修改优先级解决 |

本例选第一种，由授权业务角色确认U的调整；不是调度员擅自改承诺。系统同时保留U原请求13:30与确认后的14:30，评价时不能抹掉原请求。

如果修复延迟，12:30方案仍须再次更新。发布计划只能使用最新已确认条件；预测恢复时间可以支持场景规划，不能作为设备已恢复的事实。

## 6. 从页面到动作：最小任务记录

| 字段组 | 例子 | 作用 |
|---|---|---|
| 对象 | task=T-B-03、lot=B、step=PHOTO-120、visit=1 | 确定哪一次加工，不仅是哪个Lot |
| 版本 | plan=V3、route=R1、recipe=RP1 | 防止V1仍被执行 |
| 资源 | equipment=P02、材料批与掩模预留 | 防止资源冲突 |
| 时间 | 建议12:30–13:30、实际开始/结束单独记录 | 区分建议与事实 |
| 状态 | proposed→released→accepted→running→completed | 分别确认发布、接收、开工和完成 |
| 原因 | 欠产、唯一机台、资格已恢复 | 向人解释决策 |
| 异常 | 缺料事件、故障事件、重排记录 | 对应责任与后续改进 |

08:30和10:00旧任务应被取消或取代；不能删除历史记录。当设备完成消息重复上报，MES只登记一次加工完成。这些规则在[MES实务](03-mes-and-npi.md)展开。

## 7. D29：实际良率不及计划，交付如何闭环

假设经过本文未逐步模拟的剩余路线与后段，D29实际质量放行结果如下。为演示，A/B符合原预测，C比预测少250颗。

| 来源 | 原预计贡献 | 实际可交付 |
|---|---:|---:|
| 预留成品 | 3,000 | 3,000 |
| A | 3,900 | 3,900 |
| B | 8,550 | 8,550 |
| C | 8,550 | 8,300 |
| 合计 | 24,000 | 23,750 |

此时缺口250颗，不能把计划数当实绩，也不能默认重新投片能在D30前完成。

本例补充事件：最初隔离的300颗在D29经过既定检验得到正式质量放行，且版本适用、客户接受、未被其他订单占用。计划员从中分配250颗补足SO-001，剩余50颗可用。若未放行，则只能寻找其他合格供给或协商部分交付、改期，不能为完成订单而绕过质量。

```text
最终可交付 = 23,750 + 250 = 24,000颗
新增放行库存剩余 = 300 − 250 = 50颗
```

D30完成拣配、出货检验、发运/交付确认，按合同定义记录是否准交。仿真中的“实际产出”也是构造数据；完整真实工厂可行性并未在本案例得到证明。

## 8. 复盘：这套案例证明了什么

- 需求抵扣必须考虑在制位置与剩余良率，不能重复扣减或计算损失。
- 采购、投料、机台加工和客户交付使用不同单位与准入条件。
- 缺料、设备故障、复资格、插单是不同事件，不能只用“延期”概括。
- 有空闲机台不代表存在合格替代能力；准入条件优先于软性排序。
- 预测产出只是计划依据，交付还要由合格实物补齐。
